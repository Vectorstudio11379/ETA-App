Reviews, Q&A and Bundles endpoints

What the ETA mobile app needs to read and post course reviews, ask and list course questions, and show and sell course bundles. Checked against the live server on 12 November 2026.

Basics

Base URLhttps://expressteck.tech/wp-json/eta/v1
FormatJSON in and out. Send Content-Type: application/json.
ErrorsAlways { "success": false, "error": "…" }. Show error to the user as-is.

Signing in

Get a token from POST /login, POST /register or POST /auth/google. Send it on every request that has the user's token:

Authorization: Bearer <token>
X-ETA-Auth-Token: <token>   # send this too; some networks drop Authorization

Tokens last 30 days after the last login. When any request returns 401, clear the saved token and send the user to the login screen.

Reviews

Show reviews on every course page. Only show the "Write a review" form when the server says the user can review.

GET/reviews?course_id={courseId}Token optional

Send the token if the user is signed in. Without it, can_review is always false.

{
  "success": true,
  "course_id": 979,
  "course_title": "THE COMPLETE GRAPHIC DESIGN MASTERCLASS",
  "average_rating": 4.9,
  "reviews_count": 2,
  "satisfaction_pct": 99,
  "rating_breakdown": { "5": 2, "4": 0, "3": 0, "2": 0, "1": 0 },
  "reviews": [
    {
      "id": "209",
      "name": "SAMSON EMMANUEL",
      "title": "The",
      "content": "This is interesting",
      "rating": 5,
      "date": "7 hours ago",
      "avatar": "",
      "is_verified": true
    }
  ],
  "can_review": false
}
POST/reviewsToken required
FieldTypeNotes
course_idnumber or stringRequired.
rating1–5Required. Values outside 1–5 are clamped.
titlestringOptional.
contentstringRequired, not empty.
 
POST /wp-json/eta/v1/reviews
Authorization: Bearer <token>

{ "course_id": 979, "rating": 5, "title": "Clear and practical", "content": "The design briefs were the best part." }

The review is credited to the signed-in account. Any author_name or author_email you send is ignored. A user can review a course only if they bought it (website order or app payment) or have started watching it (website progress, or at least one lesson saved with POST /progress).

StatusError textWhat to do
201none; body has reviewClear the form and reload GET /reviews.
400Valid course_id is required. / Review content cannot be empty.Show the error under the form.
401Please sign in to review this course.Clear the token and go to login.
403Only learners who have bought or started watching this course can review it.Hide the form and show the message.
409You have already reviewed this course.Hide the form.

Course Q&A

Anyone can read the questions. Only signed-in users can ask or reply, whether or not they bought the course, so people can ask before buying. /qa is an alias for /course-qa, and /qa/reply for /course-qa/reply.

GET/course-qa?course_id={courseId}No token needed

qa_items lists the academy's built-in FAQs first (type: "faq"), then up to 50 student questions, newest first (type: "question"). Each question appears once and has an id; use it as the list key and to reply. FAQ items have id: null and can't be replied to.

FieldUse it for

POST/course-qaToken required

Course bundles

GET/bundlesNo token needed

Returns every bundle sold on the website (currently 4), read from the website's store, so names, courses and prices always match the website. The old app-only bundles 101 and 102 are gone; drop them from any saved cart.

A plain list. The response is [ { … }, … ], like /courses. Send the token to get isEnrolled (the user owns every course in the bundle).

      "title": "Global Remote Career & Virtual Assistant Bundle",
      "category": "Course Bundle",

          "price": 0, "regular_price": 0, "thumbnail": "https://…" }

FieldUse it for
id / product_id / bundle_idThe bundle's ID (668–671 today). Put this ID in the cart and send it to checkout. It is not a course ID: don't call course endpoints with it.
price, original_price, savings_percentPrice shown to the user, in NGN, identical to the website. originalPrice, regular_price, sale_price and discount are duplicates kept for older app builds.
course_idsThe included courses' IDs. Use these to link to course pages and to mark owned courses.
coursesThe included courses with title, price and thumbnail, ready to list.
packagesCourse titles only. Don't treat these as IDs.

Checkout: bundles and courses together

Send every cart item's ID, bundles and courses mixed, to POST /payment/initialize (alias /checkout/initialize-paystack). The server prices each item itself: a bundle at its website price, a course at its own price. A course that is also inside a bundle in the same cart is charged once. After /payment/verify, every course in every bundle plus each single course is unlocked.

POST /wp-json/eta/v1/payment/initialize
Authorization: Bearer <token>

{ "items": ["671", "955"], "email": "learner@example.com", "name": "Samson Emmanuel" }
{
  "success": true,
  "authorization_url": "https://checkout.paystack.com/…",
  "access_code": "…",
  "reference": "ETA_MOB_…",
  "order_id": 1132,
  "items": [
    { "id": 671, "title": "Financial Freedom & Global Trading Mastery", "price": 20000, "type": "bundle", "course_ids": [373, 470] },
    { "id": 955, "title": "THE COMPLETE CONTENT WRITING MASTERCLASS", "price": 5000, "type": "course" }
  ],
  "amount": 25000,
  "currency": "NGN"
}

amount is what Paystack will charge. If it differs from the cart total shown in the app, the app's prices are out of date: reload /courses and /bundles.

Free carts. If every item is free, there is no Paystack step: the response has free_enrollment: true and an empty authorization_url, and the courses are already unlocked. Clear the cart and open My Courses. The user must be signed in (401 otherwise).

App checklist

  1. Bundles: read the list from response.data, and use course_ids (not packages) as the included course IDs.
  2. Tapping a bundle opens a bundle page; don't look the bundle ID up as a course. Remove any saved cart items with the old bundle IDs 101 or 102.
  3. Reviews: load GET /reviews with the token, show the form only when can_review is true, and handle 401, 403 and 409 as in the table.
  4. Q&A: load GET /course-qa; key items by id; show replies under each question; show the "Ask" and "Reply" boxes only to signed-in users; handle 400, 401, 404, 409 and 429.
  5. Checkout: send all cart IDs, bundles and courses together, in one /payment/initialize call; handle free_enrollment.
  6. Send both Authorization and X-ETA-Auth-Token on every request made while signed in.
  7. On any 401, clear the saved token and return to the login screen.
Example payloads come from the live server; review and student-question samples are abbreviated. Full endpoint list: ETA_Mobile_API_Endpoints.md in the project.
