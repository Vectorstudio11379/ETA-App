Reviews, Q&A and Bundles endpoints

What the ETA mobile app needs to read and post course reviews, ask and list course questions, and show and sell course bundles. Checked against the live server on 12 November 2026.

Basics

Base URLhttps://expressteck.tech/wp-json/eta/v1
FormatJSON in and out. Send Content-Type: application/json.
ErrorsAlways { "success": false, "error": "…" }. Show error to the user as-is.

Signing in

Get a token from POST /login, POST /register or POST /auth/google. Send it on every request that has the user's token:

Authorization: Bearer <token>
X-ETA-Auth-Token: <token>   # send this too; some networks drop Authorization

Tokens last 30 days after the last login. When any request returns 401, clear the saved token and send the user to the login screen.

Reviews

Show reviews on every course page. Only show the "Write a review" form when the server says the user can review.

GET/reviews?course_id={courseId}Token optional

Send the token if the user is signed in. Without it, can_review is always false.

{
  "success": true,
  "course_id": 979,
  "course_title": "THE COMPLETE GRAPHIC DESIGN MASTERCLASS",
  "average_rating": 4.9,
  "reviews_count": 2,
  "satisfaction_pct": 99,
  "rating_breakdown": { "5": 2, "4": 0, "3": 0, "2": 0, "1": 0 },
  "reviews": [
    {
      "id": "209",
      "name": "SAMSON EMMANUEL",
      "title": "The",
      "content": "This is interesting",
      "rating": 5,
      "date": "7 hours ago",
      "avatar": "",
      "is_verified": true
    }
  ],
  "can_review": false
}
POST/reviewsToken required
FieldTypeNotes
course_idnumber or stringRequired.
rating1–5Required. Values outside 1–5 are clamped.
titlestringOptional.
contentstringRequired, not empty.
 
POST /wp-json/eta/v1/reviews
Authorization: Bearer <token>

{ "course_id": 979, "rating": 5, "title": "Clear and practical", "content": "The design briefs were the best part." }

The review is credited to the signed-in account. Any author_name or author_email you send is ignored. A user can review a course only if they bought it (website order or app payment) or have started watching it (website progress, or at least one lesson saved with POST /progress).

StatusError textWhat to do
201none; body has reviewClear the form and reload GET /reviews.
400Valid course_id is required. / Review content cannot be empty.Show the error under the form.
401Please sign in to review this course.Clear the token and go to login.
403Only learners who have bought or started watching this course can review it.Hide the form and show the message.
409You have already reviewed this course.Hide the form.

Course Q&A

Anyone can read the questions. Only signed-in users can ask, whether or not they bought the course, so people can ask before buying. /qa is an alias for /course-qa.

GET/course-qa?course_id={courseId}No token needed

qa_items lists the academy's own answered questions first, then up to 20 recent student questions (newest first). Student items also carry author and date. Items have no id, so use the list index as the key.

{
  "success": true,
  "course_id": 979,
  "count": 19,
  "qa_items": [
    {
      "question": "What tools or devices do I need for this course?",
      "answer": "You can take this course using either a smartphone (iOS or Android) or a laptop/desktop computer with a stable internet connection.",
      "badge": "Requirements"
    },
    {
      "question": "Can I export my designs as PDF?",
      "answer": "Thank you for asking! Our instructors have received your question and will answer it shortly.",
      "badge": "Student Q&A",
      "author": "Samson Emmanuel",
      "date": "2 hours ago"
    }
  ]
}
POST/course-qaToken required
FieldTypeNotes
course_idnumber or stringRequired.
questionstringRequired, 5–1000 characters.
 
POST /wp-json/eta/v1/course-qa
Authorization: Bearer <token>

{ "course_id": 979, "question": "Can I export my designs as PDF?" }

The question is credited to the signed-in account and the instructor team gets an email. On success, add the returned qa_item to the top of the list instead of reloading.

{

StatusError textWhat to do

Course bundles

GET/bundlesNo token needed
The list is wrapped. The response is { "success": true, "data": [ … ] }. Read the bundles from data, not from the top level. Reading the top level is why bundles showed up empty in the app.
{
  "success": true,
  "data": [
    {
      "id": 102,
      "bundle_id": 102,
      "slug": "creative-freelancer-pack",
      "title": "Creative Freelancer Pack",
      "subtitle": "High-converting copywriting, content writing, and graphic design for freelance success",
      "instructor": "Express Tech Academy / Coach Denis",
      "category": "Creative & Freelance",
      "original_price": 12500,
      "price": 8500,
      "savings_amount": 4000,
      "savings_percent": 32,
      "currency": "NGN",
      "currency_symbol": "₦",
      "badge": "Top Choice (Save 32%)",
      "thumbnail": "https://expressteck.tech/wp-content/uploads/2026/10/2.jpeg",
      "course_ids": [954, 955, 979],
      "courses_count": 3,
      "packages": ["THE COMPLETE COPYWRITING MASTERCLASS", "…"],
      "courses": [
        { "id": 954, "title": "THE COMPLETE COPYWRITING MASTERCLASS", "slug": "copywriting-masterclass",
          "price": 5000, "regular_price": 10000, "thumbnail": "https://…", "instructor": "…" }
      ],
      "checkout_url": "https://expressteck.tech/checkout?bundle_id=102"
    }
  ]
}
FieldUse it for
id / bundle_idThe bundle's ID (101 or 102). It is not a course ID: don't call course endpoints with it.
price, original_price, savings_percentPrice shown to the user, in NGN. originalPrice, sale_price and discount are duplicates kept for older app builds.
course_idsThe included courses' IDs. Use these to link to course pages and to mark owned courses.
coursesThe included courses with title, price and thumbnail, ready to list.
packagesCourse titles only. Don't treat these as IDs.

Buying a bundle

Start checkout with POST /payment/initialize (alias /checkout/initialize-paystack) and pass the bundle's ID. The server charges the bundle price and enrolls the user in every course in it after /payment/verify.

POST /wp-json/eta/v1/payment/initialize
Authorization: Bearer <token>

{ "bundle_id": 102, "email": "learner@example.com", "name": "Samson Emmanuel" }

The app currently sends { "items": ["102"] }, which also works, as long as the ID is sent as a string.

Check out bundles on their own. If a single checkout contains a bundle and other courses, the server charges and enrolls only the bundle. Until that is changed on the server, the app should not let a bundle and other courses go through one checkout.

App checklist

  1. Bundles: read the list from response.data, and use course_ids (not packages) as the included course IDs.
  2. Tapping a bundle opens a bundle page; don't look the bundle ID up as a course.
  3. Reviews: load GET /reviews with the token, show the form only when can_review is true, and handle 401, 403 and 409 as in the table.
  4. Q&A: load GET /course-qa; show the "Ask a question" box only to signed-in users; handle 400, 401, 409 and 429.
  5. Send both Authorization and X-ETA-Auth-Token on every request made while signed in.
  6. On any 401, clear the saved token and return to the login screen.
Example payloads come from the live server; review and student-question samples are abbreviated. Full endpoint list: ETA_Mobile_API_Endpoints.md in the project.
